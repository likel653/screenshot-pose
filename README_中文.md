# Screenshot Pose · 截图转姿势 v0.39.0

## v0.39 视频脚底支撑精修

生成视频动画后，在「视频」页点击「精修脚底支撑（RGB MoCap）」。它从当前角色 Action 读取骨盆和双腿，调用 RGB MoCap 的连续接触求解，输出可编辑的独立 Action。可以点「查看精修前动作」切回，或在动作编辑器选任一版本。启用 Blender 的时间轴预览范围可以只修一段，建议在切镜、遮挡或故意滑步的片段前后分段处理。

功能使用 Windows 上已有的 RGB MoCap 和与其接触模块匹配的独立 Python（含 NumPy、SciPy）。本机配置位于识别环境的 `rgb_contact_runtime.json`。在其他电脑可从插件偏好设置选择 RGB MoCap 程序目录和其 Python。安装包提供桥接代码，RGB MoCap 及其原生模块单独准备。支撑精修只读取已生成的动画，使用 CPU，无需额外模型权重。

当前支持能读取骨盆与双腿 FK 的独立 Action。骨盆平移与骨盆旋转需在同一个根控制，腿部控制不能被其他旋转约束或驱动覆盖。修正使用推定鞋底接触，适合平地。求解无明显收益或目标回放核验失败时保留原动作。截图和常规视频生成流程仍各自使用原设置。

## v0.38：源三维姿势保护与截图自动 GPU 手部精修

新截图默认启用“保护源三维姿势”。完整源骨架实际应用成功、没有手动改动关节点时，优先保留原有深度与躯干，通过目标骨架与源关节的整体方向建立相机参考，再允许小范围图像微调。相机相对参考方向不超过 3 度；肢体每级旋转参数不超过 4 度，实际 FK 复核单骨段变化、骨长和投影改善，未通过时保留源姿势。自由躯干拟合和无接触的全身再拟合不再叠加覆盖此结果；最终关节 / 投影记录在头手脚处理后重新读取。

手动关节点、局部更新和用户选定的候选继续优先。指定接触仍可调用全身支撑协调，双脚接地在此保护步骤中只调整相机。已有有效透视标定保留内参，在保持骨架的条件下优化相机；没有有效标定则明确记录弱透视回退。源预测是先验，不是真值；遮挡或源姿势错误仍需修正。关闭保护可恢复原有自由拟合，固定样例已验证与 v0.37 几何一致。视频明确关闭这个截图专用步骤。

生成页增加“截图手部精修”，默认 `自动 GPU · HaMeR`。选择文件和框选截图都在同一个后台任务内完成身体识别，再精修双手；无需识别完成后另外点击精修。增强 HaMeR 可手动选择，原有手部精修模型设置继续用于独立局部任务。模式可以关闭。缺少模型、CUDA 失败或某只手未通过采用检查时，保留该手原观测并显示原因，不自动下载，不把回退结果标成新模型成功。手部阶段不改写身体关节或完整源骨架。

识别先建立任务自有参考快照，防止原文件被覆盖时混入另一张图。原图存在额外分辨率且通过既有像素核验时，手部模型仍可使用原图细节。最终 JSON 在手部处理结束后一次提交；取消保留当前场景数据，现有任务树取消机制覆盖子进程。截图仍立即框选、原亮度、零等待；任务状态显示身体 / GPU 手部阶段。已有权重需要用户按各模型许可准备。

固定验收配置含六张真实参考缓存和六个有相机 / FK 关节代理的灰模样例。新旧使用相同预测缓存，受控样例的身体骨段方向差平均从 18.1 度降到约 10.9 度；二维贴合可能放松。没有独立留出集，也没有真实照片三维标注，不能据此宣称所有图片精度提高。另实际运行了一张完整的身体 / 自动 HaMeR 截图任务，验证两手采用、回退、回调、预览、打帧、手动关节点和支撑兼容性。原始工程和动画保留，发布前复测安装包。

## v0.37：工作区、疑点定位与候选选择

主面板按“生成 / 修正 / 设置 / 姿势库 / 视频”分区，角色始终由用户明确选择，不依赖当前选中物体。生成页显示已识别参考图缩略图，并提供独立的“预览姿势”和“确认姿势并打帧”：预览使用临时动作显示，原动作曲线保留；确认仅烘焙最终姿势到独立动作。原有 `keyframe` 设置继续控制局部修正和候选确认。

修正页选择身体、头、左右手臂或腿，只显示相关面板。头向 GPU 准备和三维手模型环境移到设置页。姿势库、视频及其复核、接触工具保留独立入口，未更换默认模型。

“需要复核的部位”汇总低证据二维关节、模型弯曲平面分歧、局部结果未采用或回退、头向分歧、缺少手指/脚向及实际传递提示。点击定位进入相应工具。提示按角色自身左右标记，是复核依据，不是准确率；未发现提示也不代表姿势正确。当前数据、角色、帧、映射或主要求解设置改变后，不沿用旧应用的传递结论。面板绘制使用有界缓存，不启动推理或全骨架诊断。

身体深度分支在共同相机下比较实际角色关节，结合关节弯曲、弯曲平面、肩胯关系、源深度及明确接触目标的可达性。完整骨架与旧关节点方案的比较也使用同一相机和上述先验，额外保留源骨架旋转评分。没有足够优势时保留默认候选，深度候选接近时报告歧义；用户确认的候选与手动关节优先。原始完整骨架始终可作为保留基准，其结构提示单独记录；先验不证明估计深度是真值。

手部模型结果可按左/右手，选择整手、仅掌向或仅手指。拆分采用时刚性对齐掌内手指形状，保留 MANO 原生指骨旋转；不平均多个模型。另一只手、身体和原始 JSON 保留，组合写入运行目录的新文件；人工校正、失败候选及已变化的主图会阻止覆盖。选择后需局部应用，尚不自动判定哪个模型更准确。

白发角色验证了工作区 RNA/图标、任务/候选禁用状态、预览不改写原动作、确认打帧及回放。真实缓存 HaMeR/增强 HaMeR 的重复拆分选择通过局部应用检查。视频继续沿用原有求解流程。本次不宣称整体三维识别精度提高。

## v0.36：截图全身协调与显式支撑联合求解

在“身体与原图贴合”开启“贴合原图并匹配相机”和“全身与支撑协调”。新步骤以前面的身体结果作为基准，在同一个有界目标中优化骨盆 XYZ、可写的腰胸/肩部和双臂双腿。相机保持不变，骨盆各轴位移按身体包围尺度限制；普通姿势也允许平移，不再只限双脚接地路径。原来的躯干微调仍可作为初始结果，关闭新开关即保留旧流程。

启用独立手脚接触时，先冻结本次用户指定的掌心、鞋底目标，再联合求解全身。末端保持目标位置与朝向，实际 Blender 求值后复核骨长、鞋底间隙、掌心残差、可靠图像点、头部位移和目标自身是否发生移动。约束/驱动跟随当前角色的目标会被拒绝。没有明显改善、目标无法在范围内到达或破坏关节结构时，恢复此前结果。明确的接触目标原先够不到时，允许有限的二维位置退让来满足该目标，并单独记录原因；不把这类取舍称为图像精度提升。

评分新增关节弯曲范围、弯曲平面翻转、肩胯相对方向、躯干长度变化和源深度先验；依据独立定位分数降低不可靠观测影响。所有先验和定位分数仍是估计，不能证明真实三维姿势正确。支撑由用户指定，不包含椅子识别、网格碰撞和真实重心/动力学求解。单独更新头部或手脚不会启动全身步骤。

根位移、额外肩部控制和拟合修改都会进入最终关键帧及动画副本，跨帧回放已测试；老工程的基准缓存会补齐新控制。视频显式保持此截图步骤关闭，手部模型默认值不变。四张参考图提供完整正面、侧面及原匹配相机对照；另有独立的支撑控制测试，明确区分合成目标和照片样例。

## v0.35：纹理监督 HaMeR 权重实测接入

已使用用户重新下载的作者权重 `new_hamer_weights.ckpt` 完成归档 CRC、推理网络参数匹配和真实 CUDA 推理。该文件 SHA256 为 `9b9c2858d7caa3aade793faca9e30f32a64ec8d927c97ebf9270823aa02e4954`，本地模型目录保存经过同一哈希校验的副本，原下载文件保留。主干与 MANO 参数头的 503 个张量已单独核对，确实与原版不同。

作者训练检查点额外包含 `recoLoss.*` 和 `texture_model.*`，公开的姿势推理 forward 不使用这两个训练模块。因此仅在 HAMER_TEXTURE 中排除这 217 个训练参数，推理网络的缺失键、未知键和形状仍检查；原版/WiLoR 加载方式不因此放宽。模型缺失、损坏或加载失败时不会使用原版冒充增强版。导入前校验完整归档，下载期间文件变化时拒绝修改配置。

使用：重新加载插件 → 头部与手势 → 独立三维手部重建 → 选择“纹理监督增强 HaMeR”或“原版 / 增强版 HaMeR 对比” → 精修对应手。对比模式分别保存两套结果，查看后选择，再仅更新对应手。识别与选择结果不会自动给角色打帧，默认手部模型保持原设置。

四张参考图已做同图、同定位和同裁剪策略对照。每个模型均有 7/8 只手通过几何检查，EVE 头后遮挡手均未通过。增强版的二维分数有小幅改善也有小幅退步，目前没有稳定、明显胜出；这些分数不是三维手形真值。白发角色工程提供固定相机手部近景与独立 Action，便于逐手检查。身体与头部观测、手势预设和视频默认设置不自动改变。

## v0.34：头部候选复核与躯干联合修正

截图应用默认开启“比较身体与局部头向”和“骨盆、脊柱与肩部联合修正”，均可关闭。头部同时保留身体头向及精修前的旧候选；局部高置信度本身不能覆盖更好的旧结果。头部六点 PnP 优先使用与当前工作图片内容绑定的估计相机内参；标定失效时明确退回通用焦距。眉眼、鼻梁等最多 18 个未参与六点拟合的脸点用于复核，仍受通用脸形与对应点近似影响，不代表三维角度真值。

可选“加入独立头向 GPU 候选”使用官方 6DRepNet360 Full Rotation，约 95 MB，使用现有独立三维手部 PyTorch/CUDA 环境。点击“准备独立头向 GPU 模型”后重新识别头部即可。权重严格加载并验证 SHA256，使用两种裁剪及图片旋转一致性检查，再参与同一候选复核。四张参考图已完成真实 CUDA 推理，该模型未稳定优于原头向或 PnP，因此默认关闭。推理失败保留其他候选并记录日志；不把回退标为 GPU 成功。

躯干联合修正保持已经匹配的相机，允许根控制骨、腰胸控制和可验证的肩部控制作受限旋转。对通过约束跟随的肩部做可恢复的小角度影响探测；只在实际求值后的角色投影有明确改善、可靠关节点未明显退步、骨长和接地脚踝保持时采用。肩部提案不能达到目标时可退回仅腰胸方案；显式手脚接触保持优先。该功能不自动识别椅子等场景支撑，也不求解碰撞。

视频继续使用原有流程，不自动启用本轮截图躯干和头部候选步骤。手部增强权重由用户下载中，本轮未更换手部模型。通用脸部几何来自 Google MediaPipe Apache-2.0 canonical face model，来源与 SHA256 记录在 `face_template.json`，附许可文件。

## v0.33：可选相机标定与透视拟合

在“身体与原图贴合 → 相机标定与透视”准备 AnyCalib 模型，然后对当前截图标定。默认保留原有身体与手部识别，只增加图片绑定的估计内参，手动应用后使用透视相机与肢体联合拟合。标定后再决定是否采用；投影模型仍默认“原有近似”。相机模型在独立 CUDA Python 环境运行，不导入 Blender。标定文件绑定截图像素/尺寸及工作图片哈希，输入变化时失效。

透视拟合保持骨长，保留已接地脚踝；开启双脚接地及骨盆协调时可在有界范围协调根控制骨。相机固定使用估计内参，支持非中心主点和不同水平/竖直焦距；真实 Blender 相机投影已做数值核对。接触后的投影检查和直接拖动校正同步使用对应相机模型。透视结果明显差于原近似或绑定无法达到目标时撤回提案并保留原拟合。手工指定的场景接触仍由原接触流程处理，不自动推断场景支撑。

“同时重新识别 SAM 身体”单独提供为试验开关，默认关闭：当前四图对照并未稳定胜出。支持切回标定前观测；姿势库保留投影设置与标定数据，新图片不会沿用旧图片的透视开关。视频使用原有投影流程。

实际四图对照中，蹲姿仅换透视后关节点投影误差约 15.67→8.08 px；前倾图改善很小，抬腿图没有改善，EVE 坐姿采用回退。二维误差不是三维准确率。完整对照包含四个条件：原身体/原拟合、原身体/透视、标定后身体/原拟合、标定后身体/透视。

新增可选 `HAMER_TEXTURE` 与原版/增强版对比入口。作者公开的纹理监督权重链接目前要求登录，自动下载返回 403；本机尚未获得该增强权重，因此不提供增强版识别效果结论。用户取得作者 `.ckpt` 后可选择并“核验增强权重”：严格检查网络结构并记录 SHA256，拒绝把与原版相同的权重登记为增强版。缺权重时明确拒绝增强版识别，不把原版回退结果标为增强版成功。

## v0.30：WiLoR 与 HaMeR 独立三维手部后端

在“头部 / 手掌”面板的“独立三维手部重建”选择 WiLoR、HaMeR 或双模型对比，然后点击对应左手 / 右手精修。双模型分别保存 21 个三维关节、原图投影、识别来源和失败原因；不会自动选择赢家。查看对比后可选择任一结果，再“仅更新对应手”。切换候选不自动应用角色或打关键帧。现有局部模型仍为默认值。

## v0.29：局部时序状态、仲裁与高频复核

补上短遮挡时的局部状态：手腕在前臂坐标下、手指在局部控制坐标下保存有限记忆。默认上限 0.35 秒，前 0.12 秒内短暂保留，之后平滑退出；有可用恢复观测时优先做前后帧补间。新的已应用观测会消费旧记忆，镜头/跟踪重置、长间隔、人工手势及控制依赖变化会清空状态。会增加恢复跳变的前向建议直接拒绝。这里估计的是短时连续性，不是被遮挡动作的真值。

“手腕可疑短段修正”只考虑前后方向接近、二维掌面变化较小、跨度受限的可疑片段。可靠三维转腕保留；三维掌骨比例突变还需前后形状一致、二维证据一致才允许替换。经当前角色的实际 FK 绑定换算为手腕通道，并验证手腕位置、原弯曲限位和旋转残差。四元数正负号用最短弧误差检查，避免等价姿势被误报为 360° 失败。

局部仲裁优先级为识别数据中的人工/可靠观测、可靠前后帧衔接、有限记忆、原始身体/基准预测；人工手部编辑同时阻止旧异常修补和平滑覆盖。诊断标记独立于平滑决策。本轮统一范围是手腕与手指，SAM 主体仍逐帧生成候选，全身的头、脚、身体多源仲裁尚未统一。原 Action 上的手工修正保留在原动作，不会自动移植到重新生成的新动作。

修复高频缓存复核：30 次/秒的观测落到 24 FPS 时允许重复输出帧映射，按原始时间找参考图；人物未检出采样也保留对应图像/提示。当前场景 FPS 改变不会误配原生成时间。区间修正新增“仅左/右手腕”，定位手腕问题会优先选择该范围，保留前臂、手指及区间外通道。

同一 15 秒、157 个识别姿势、同一核心开关对照，保持 360 帧：实际回放的相邻观测间 >90° 手腕变化左侧 16→15、右侧 20→15。涉及有限记忆的 781 个指关节相邻观测对中，>45° 变化 367→253，中位数 38.3°→16.6°；这是连续性指标，不是识别准确率。身体和手腕位置、非手部通道保持一致，骨盆起伏与自动支撑保留。未采用的单向记忆试验也保留，便于复核恢复帧的回退。

已有识别缓存可以重新生成以使用这些改进。提升真实采样密度仍须重新识别；新增插值、记忆或补间不算新的模型识别。可靠观测本身错误、长期遮挡和深度歧义仍需人工复核或后续模型级改进。

## v0.28：视频骨盆、自动支撑与动作重采样

修复视频始终原地的问题：原流程每个采样恢复骨盆位置，SAM 源骨架也使用固定根位置。新增“相对高度”（默认）、“相对画面位移”和“原地”模式。以每个连续镜头的稳定腿长投影尺度，把图像骨盆位移转成角色尺度；跟踪中断后重新建立参考。没有可靠的绝对世界轨迹、前后位移或镜头运动解耦。移动镜头下建议仅高度或关闭位移。

“自动脚部支撑”默认开启：从连续低速且靠近画面地面的脚提出支撑候选，使用鞋底校准建立固定落点，逐工程帧执行骨盆有界调整与 FK / 两段 IK。区间首尾渐入渐出；不跨失跟/镜头切换，不把较高的抬脚强制压地。缺少鞋底参考或可写控制链会提示跳过；不可达的腿部求解撤回，不拉伸骨长。复核列表记录候选与失败帧，用户仍可关闭自动支撑，或用原有的接触区间功能手动校正。它不是受力平衡或动力学仿真，不能自动理解台阶、椅子和移动支撑物。

“采样间运动”默认有界曲线：保留原始观测时间戳，不先丢弃落到同一工程帧的高频观测；用最短弧局部四元数曲线和单调有界 Hermite 位移重采样，按场景帧率逐帧烘焙。大角度回退到 SLERP；FK/IK 开关保持常量。整人漏检、镜头切换和失跟间隔保持前姿势，片头/片尾不足时采用首/末有效姿势并记录保持时长。可选 SLERP 或原采样关键帧模式做对照。插值不会创造漏采的快动作细节。

界面新增运动自适应采样：低分辨率光流预扫描后，在快速画面运动区增加真实模型推理采样，并保留基础采样点和采样预算。0 仍表示逐帧识别。新策略仅在重新识别视频/录屏时生效；已有缓存可直接享受骨盆、支撑和插值改进。现有命令行调用保持 FIXED 默认，可传 `--sampling ADAPTIVE --max-sample-fps 30` 开启。

实测使用同一白发角色 15 秒缓存：157 个识别姿势重采样为 360 帧；实际骨盆世界高度跨度从 0 变为约 0.442 场景单位。提出 6 段支撑候选，共 123 次单脚逐帧求解，接受 121 次、拒绝 2 次；满权重且接受的 108 个帧次已用保存工程的实际回放复核约束残差，不等于姿势识别精度。额外两秒 GPU 自适应采样烟测从 12 个基础点增加到 21 个真实 Vulkan 结果（置信度 0.75）；0.5 的测试触发背景多人保护并中止，保护未被跳过。源工程及原动作保留。

## v0.24：视频自适应连续性

视频生成新增“连续性处理”：默认自适应，也可选固定平滑对照或关闭。自适应模式在四元数切空间按真实时间戳做居中的局部线性拟合，并按可信度加权；快速运动和明显转折会减弱平滑。处理使用前后帧，不推迟关键帧时间。首尾、长时间中断和需要人工复核的翻转保持不变。位移转折也单独保护，骨骼缩放不平滑。

异常复核新增短段翻转修补：仅当连续至少两个低置信度样本位于可靠前后帧之间、总跨度不超过 0.3 秒、前后旋转接近且整个短段均明显偏离时才插值。高置信度大动作不自动替换，持续错误不外推。原始识别缓存保持不变，修改只写入新动作。

这些属于已有预测的时序整理，不能解决持续识别错误、遮挡造成的深度歧义或镜头切换。受控测试可验证去抖、转折保持和异常修补；自然视频没有真值时，只报告变化与稳定性指标，不把“更平滑”当成“更准确”。

## v0.23.2：修复视频背景误检与错误提示

RTMLib 对内置 NMS 的 YOLOX 模型固定使用 0.3 阈值，忽略传入的置信度。现在三条 RTMW / RTMW3D / SAM 识别路径统一按用户设置过滤这类输出。实测用户单人视频第 292 帧中的两个背景框分数为 0.359 和 0.321，设置 0.5 后会正确排除；可信的多人检测仍会停止视频识别，不会静默切换人物。

任务失败时优先提取明确的错误消息，避免把退出时才刷新的模型加载提示误报为失败原因。多人停止提示包含视频时间及源帧号，可定位并重新框选或裁短范围。

## v0.23.1：修复录制控制窗卡住

Windows 上，Blender 读取 `progress.json` 的短暂时刻可能阻止录制进程替换该文件，出现 WinError 5。v0.23 会把异常抛出 Tk 控制窗的进度回调，导致消息轮询不再调度：视频已录完，但控制窗处理不到完成消息，后续识别没有启动。

现在原子文件替换遇到 Windows 短暂共享占用会有限重试；进度写入是非关键通知，失败不影响录制和识别。控制窗合并旧进度、优先处理完成消息，并隔离进度回调异常。真正的视频与结果文件仍严格保存，不能把保存失败误报为完成。

回归测试包含真实 Windows 读句柄占用、持续占用的有限重试、进度回调异常、完成消息投递，以及实际选区录制时触发同样 WinError 5 后继续自动识别。进度异常不再让录制控制窗停在剩余几秒。

## v0.23：框选屏幕视频，按时长录制并识别

在“视频转动画”中把视频来源切到“屏幕录制”，设置录制时长（默认 5 秒）、录制帧率（默认 15fps）和识别模型，然后点击“框选录制并识别”。

1. 立即出现原亮度的桌面框选界面，没有 3 秒等待。拖框选中播放器中的人物区域，松手完成选区。使用与单张截图相同的双屏坐标体系，支持副屏位于主屏左侧 / 上方的负坐标。
2. 录制控制窗准备好后，播放视频，再点击“开始录制”。控制窗尽量放到选区外；如果选区覆盖所有可用位置，开始后自动隐藏。录制期间保持播放器可见、位置不变；当前功能记录固定屏幕区域，不随窗口移动，也不从最小化或被遮挡的窗口提取画面。
3. 到指定时长自动结束。勾选“录完自动识别”时，随后运行所选模型并缓存姿势；识别完成后点击“生成到所选角色”。录制和推理分开进行，SAM 运行较慢不会拖慢前一阶段录制。
4. 关闭自动识别时只保存本地视频，之后可选择模型再点击“识别录制视频”。录制文件与姿势缓存放在识别环境的 `screen_videos/独立编号/` 内；界面“录制文件”可以重新使用。

Esc / 控制窗取消按钮可取消框选或录制，未完成视频会清理；Blender 的“取消当前任务”也可结束工作进程。取消选区或录制保留原视频路径和原姿势缓存；已经完成录制、后续识别失败或被取消时，保留可用录制文件，供再次识别。刚生成的录制文件会清空旧视频的时间范围和旧姿势缓存，避免误把上一段动画用于新视频。

当前 Windows 录制只保存选区画面，不录声音。使用 MJPEG AVI 便于本地解码和复用，体积可能较大；最长边最多 1600 像素。偶数编码尺寸可能在右 / 下补一像素边缘。若采集速度跟不上，使用重复帧维持时间轴长度，并在录制摘要标出数量；不会把慢采集直接变成加速播放。帧数取整可能使视频时长相差不到一帧。先用 2–5 秒测试，确认人物完整清晰后再录制较长片段。

本轮通过独立的可见测试播放器实测选区采集：1.6 秒、15fps 得到 24 帧，随后以快速模式识别 16 个采样姿势，并生成到 Velina 白发角色。另验证了低速采集补时、负坐标选区逻辑、原亮度显示、取消清理、识别失败保留录制和原生 Blender 入口。它验证录制到角色的链路，不代表所有播放器或遮挡动作的识别精度。

## v0.22：常驻推理、角色适配加速与异常跳变复核

SAM 视频模式现在在本次视频任务中保留原生 Vulkan 模型、RTMW/RTMW3D、人体、头部和手部识别实例。后续帧复用同一组模型，任务结束释放资源；取消任务继续使用进程树清理。保持 F32 权重、原有裁剪和各帧独立识别配置，不以换小模型或跳过识别换取速度。需要 sam3d 原生运行器支持 `--worker` 协议；本机运行器已更新 Windows 二进制请求读取。

- 本机同一视频前 2 秒、3fps 共 6 帧：原流程 38.6 秒，常驻流程 14.3 秒，约 2.7 倍；这 6 帧的原生人体关节 / 旋转、参考点数值一致。计时是本机单次对比，长片、显存和其他负载会影响结果。
- “加速角色适配”默认开启：本次任务的静置鞋底校准只计算一次；完整身体和指骨按父子深度分组，更新父骨后再计算子骨，减少重复场景求值。原有单图流程仍逐骨更新。对相同 3 个 SAM 姿势，Velina / Gwen 本机约快 1.7 倍，全部求值骨骼矩阵一致；特殊绑定可关闭此开关重新生成对照。
- “复核异常跳变”默认开启：只检查间隔不超过 0.5 秒的三帧窗口。中间控制骨偏离前后帧插值至少 80°、前后差异小于 35°、中间置信度低于 0.55 且两侧不低于 0.55 时，才用时间加权四元数插值修补。高置信度大动作、相邻证据不足的疑点只记录，避免用插值替换真实动作；标记但未修补的旋转峰值也不参与普通邻域平滑。
- 原识别 JSON 和原始求解缓存保持不变；修补只写入新 Action。完成后“查看视频复核结果”显示自动修补数量、待检查帧及控制骨、生成耗时。没有标记不等于识别正确。连续多帧错误、左右腿整体认错、被长期遮挡的手脚和世界位移仍不在此复核的恢复范围内。
- 短暂的局部失跟还可在可靠前后帧之间补间：中间分数不超过 0.15，可靠边界总跨度不超过 0.3 秒，两侧差异不超过 100°，才修补偏离至少 15° 的缺失旋转。开头、结尾及长时间缺失不外推；这类模型分数只是筛选线索，并非标定后的正确率。
- 姿势文件在可取消的逐帧适配阶段验证，避免开始生成前一次性读取全部大 JSON。无效数据仍沿用完整回滚。所有阶段继续保留原 Action、NLA、取消与错误恢复。

复核验证包含可重复的“人为注入单帧小腿翻转”故障测试，以及真实视频连续采样测试；前者证明修补链路有效，不代表自然视频精度评分。稀疏到 3fps 的数据缺乏足够近邻时不会自动补帧纠错，建议动作较快的视频使用 12fps 或更高采样率。

## v0.21：本地视频转角色动画

展开“视频转动画”，选择本地 MP4 / MOV / AVI 视频，设定开始 / 结束秒和每秒识别帧数，点击“① 识别视频并缓存”。结束秒为 0 表示读到结尾；识别帧率为 0 表示逐帧识别，默认每秒 12 帧。低采样率会减少识别次数，但不会改变动画时长。当前按视频标称固定帧率换算时间；手机可变帧率素材建议先转为固定帧率。

- SAM 高质量 GPU：沿用已安装的 SAM 全身、手脚模型，逐帧处理；原生运行器每帧重载，长片段耗时较长，建议先测试 2–5 秒。快速 CPU 模式使用一个持续的 MediaPipe 视频跟踪实例，适合预览身体动作，缺少独立手指精修。

- 写入全新独立 Action，原 Action 的关键帧不修改，NLA 暂停以避免覆盖生成结果。FK 控制、必要的 FK/IK 开关、指骨一起打帧。使用“恢复生成前动画”恢复原 Action 和 NLA；生成结果仍在动作列表，保存自己的 .blend 可以保留。
- 同一来源贯穿整段，不逐帧挑选身体候选。按时间范围对旋转、位移轻度平滑，统一四元数符号，并使用线性插值避免 Euler 绕圈和贝塞尔过冲。平滑为 0 关闭，默认 0.12 秒；平滑不能恢复模型认错的三维结构。
- 短暂整帧漏检允许补间，超过设定时长则停止生成；开头 / 结尾漏检不外推，时间位置保留。检测到多个人物会停止，避免按面积排序时悄悄换人。当前适用于单人、连续镜头，不支持多人身份追踪或自动切镜头。
- 两个步骤都有进度和取消；生成阶段分批进行，取消或报错恢复生成前的骨骼、动画、播放范围。识别中断保留已生成的临时文件，但不将未完成数据作为可用缓存，也尚不提供断点续跑。
- 当前生成原地动作，不估计行走轨迹、物理支撑或自动锁脚。不继承单张图的手势预设、掌向修正、地面和接触目标。“逐帧贴合原图”默认关闭，避免额外耗时与独立相机拟合引入抖动；有需求时可以显式开启。

视频只在本地解码和识别；视频网址需先保存为本地文件，本版本没有内置网站下载功能。推荐原始清晰视频；低分辨率、遮挡、极端抬腿和小手部区域仍会影响质量。

## v0.19：修复不打帧时腿脚外观不跟随

白发角色原有 Action 包含 FK/IK 开关曲线。此前应用计算出的 FK 控制骨已经转动，但恢复原 Action 后，动画又把开关切回 IK，变形骨继续跟随旧 IK。因而会出现上半身变化、腿脚仍站直的现象；仅检查 FK 控制骨矩阵会漏掉这个问题。

现在“不打关键帧”在独立的临时 Action 副本上屏蔽本次姿势涉及的动画通道，并暂时暂停 NLA，使 FK 控制骨、绑定开关和实际模型同步。原 Action 的曲线、关键帧和静音状态保持不变。换帧、恢复原姿势、切换工程或关闭插件时退出临时状态，恢复原动画。面板会显示临时姿势提示；要跨帧保留，请勾选打关键帧并重新应用。

本次用 EVE_COOLING 坐姿图在原始 Velina 工程复现，同时检查脚、大腿和小腿的实际变形骨，对照完全断开动画的结果、换帧恢复与已打帧回放。未修改原始 .blend，未使用手工坐姿修正。它修复了绑定不跟随，并不证明坐姿深度、接触或头手朝向已经准确。

## v0.18：修复 SAM 自动脚向来源

SAM 数据的自动脚向现在使用 MHR 原生脚骨全局旋转，按原生 Y 向上的静置坐标系建立足底参考，再映射到目标角色鞋底。此前自动应用使用了独立 RTMW3D 的脚尖/脚跟估计，导致 SAM 原生脚部方向被覆盖，脚底可能明显翻转或侧翘。踝到前脚掌的高度差也不再被当成鞋底倾角。

这是自动应用流程修复，不需要选择水平候选或手动指定支撑；已有 SAM 缓存中保留完整源骨架的，可直接重新应用，无需重新下载模型。用户明确确认过的脚向仍优先；如果旧的人工候选不适合，请选左右脚后点击“恢复此脚 SAM 自动朝向”，再应用。该按钮保存新 JSON，不覆盖原识别数据。

此修复限定 SAM/MHR 原生骨架数据。非 SAM 数据沿用原路径，不声称它们的脚向同时被解决。脚踝位置、交叉腿深度、接地与遮挡仍可能不准；原生模型旋转本身也不是人工真值。

## v0.17：脚部局部复核与脚向预览

“脚部与接地”顶部新增：

1. **两尺度局部复核双脚**：用已安装的 RTMW 模型，对包含髋、膝、踝和脚部的局部区域做两种尺度推理。按照原腿链匹配左右归属，拒绝脚踝大幅漂移、脚跟脚尖重合、低分或跨尺度不一致的结果。未通过者保留原脚；通过者保存新 JSON，尚不改变角色。此步骤沿用原深度，只细化二维观测，模型分数也不是校准后的三维准确概率。
2. **预览脚向**：选择人物自身左右脚，比较原脚向、反向鞋尖、翻转足底三个几何假设。它们不是三个独立模型预测，也不会自动挑选“正确”候选。预览暂停当前 Action/NLA，确认沿用打帧设置并复制 Action，取消恢复原姿势。已有支撑约束会保持鞋底支撑；某些候选因此会被压成相同的水平姿态。
3. **识别 / 角色脚向诊断**：生成蓝色识别脚点/朝向和橙色实际鞋底/朝向的视口快照，使用物体或材质颜色观察。它不进入渲染，不会随骨骼自动更新；修改姿势后请刷新，或点击隐藏。

脚向确认只更新选中脚的朝向；有支撑时仅调整该侧腿，不改变骨盆。超出骨长仍会报告残差。局部识别与候选都不保证恢复遮挡脚的真实深度，不包含高跟鞋、靴子或脚趾专用的新训练模型。

## v0.15：原图叠加与目标角色直接拖动

先正常识别，使用图片 / 混合模式开启“贴合原图并匹配相机”并应用到目标角色。展开“叠图与直接拖动”：

1. 点击“显示原图 / 进入匹配相机”。参考图叠在实际角色上方；“原图显示强度”0 表示隐藏、1 表示完全显示。此图使用相机的视口参考图，不进入最终渲染。原有参考槽不被替换；隐藏时仅移除插件创建的槽和图像副本。原来关闭叠加层时会临时打开，隐藏后恢复。
2. 选择人物自身左 / 右手腕或左 / 右脚踝，点击开始，再在视口拖动亮色圆点。固定肩部 / 骨盆、另一侧肢体和其他控制骨，只对对应 FK 两段肢体求解，保留手掌 / 脚的世界朝向与实际骨长。原动画在临时预览期间暂停，驱动仍然生效；取消恢复原 Action 和 NLA 轨道开关。
3. 拖动是匹配相机平面内的修正，沿用该端点当前深度，不自动恢复遮挡部位的深度。超出骨长时显示最近可达位置和残差，不拉长人物。脚踝可开启“保持当前高度”；此时上下拖动受到限制，适合已接地的脚。关闭则可能离地，不会自动拖动骨盆或另一只脚。
4. 按 B 比较拖动前后，Enter 确认，Esc / 右键取消；侧栏也有对应按钮。确认时沿用主面板打帧选项，复制原 Action 后只给此肢体和必要 FK 开关打帧。未打帧的临时姿势在换帧时仍可能被原动画覆盖。
5. 确认会把此肢体的肘 / 腕或膝 / 踝投影同步到已有二维关节点，保留未修改点和原深度；不覆盖原姿势 JSON。保存自己的 .blend 可保存这些关节点。之后重新运行全身拟合仍可能调整身体，不能把本次拖动当作永久硬锁。

“撤销上次已确认拖动”提供单步恢复，包含原姿势、Action、备份及关节点。仅允许在同一角色、帧、姿势数据且没有后续人物 / 关节点 / 关键帧 / 轨道修改时使用，避免覆盖新编辑；切换角色会清除此撤销记录。预览期间改变帧、相机、工程或源数据会停止 / 拒绝继续，并支持恢复。它不包含碰撞求解、物体握持或所有 IK / 自定义控制器兼容性。

测试包含两个实际角色的四个端点、不可达目标、脚踝高度锁定、对比 / 取消 / 确认、动画暂停恢复、单步撤销保护；另在独立 Blender 窗口模拟真实鼠标和键盘事件，保存原生视口截图。演示拖动是人工操作，不是模型自动识别改善，也尚未测得真实用户修正时间的下降。

### 三维数据与手部质量回退

- 身体的两个深度候选共用 RTMW 384×288 的二维观测，避免只用各自预测评价自己。自动选择依据投影误差，仍不能证明三维真实。

- 使用三维脚踝、大脚趾、小脚趾和脚跟，求脚部朝向；接地启用时约束鞋底参考平面朝向地面，保留目标角色本身的高跟鞋/鞋型。

- 使用的是相对脚骨的刚性鞋底参考，不是完整蒙皮接触或布料碰撞模拟。弯曲脚趾、脚掌变形、姿态相关形态键可能造成实际网格偏差；需要渲染检查。

### 本机最短使用流程

### 当前识别方案

- 身体：RTMW 133 点提供定位，MediaPipe 身体模型提供估计深度。
- 头部：按面部区域进行多种尺寸的裁切，优先使用 MediaPipe Face Landmarker 的完整面部旋转矩阵。失败时尝试 RTMW 面部六点 + 通用脸形 PnP；再失败则保留原有姿势，允许角度微调。
- 手部：以 RTMW 左右手区域为依据，尝试两个裁切尺寸及 0/90/180/270 度旋转；把检测点及三维手点变换回原图相机坐标，以重投影一致性选择候选。
- 三维手模型失败时，用 RTMW 的腕部及四个指根，结合通用掌面形状做平面 PnP，标记为 **掌面几何估计**。它可能有深度和掌背歧义，支持有效候选切换与翻转，不能等同于真实三维重建。
- 这些局部匹配评分由关节点投影一致性构成，不是经过统计校准的“正确率”。

此图的实际路线：头部使用面部模型，右手使用三维局部手模型；遮挡较多的左手使用掌面几何估计。不是两只手都被三维模型成功识别。

### 旋转求解与角色适配

- 头部采用完整旋转坐标系，分开处理左右转头、抬低和歪头。先给颈部分配一部分旋转，再设置头部绝对朝向，避免父子旋转重复叠加。
- 掌面由腕部、食指/中指/小指指根构建，避免使用弯曲指尖推算掌心。
- 每次应用从目标角色静置骨架读取掌面参考轴，不修改静置骨骼。ARP 已自动适配；其他模型可在高级选项指定左右食指根、小指根参考骨。
- **校准角色方向**按钮读取并记录当前静置参考信息；角色方向和参考骨设置保存在场景中，每次应用按当前设置计算。无需先把角色手动摆回 T 姿势。
- 三维结果从图片相机坐标转换到已匹配相机及骨架对象坐标，再写入 FK 控制骨，兼容静置骨轴方向与对象旋转。
- 根据前臂长轴分解手掌请求的扭转，默认将 70% 分配给可写的前臂 FK 控制；其余由手腕承担，并限制过大的腕部摆动。若扭转前臂导致手腕位置漂移，会退回该分配。保留绑定已有的扭转骨与驱动，不直接覆盖受驱动的变形骨。
- 自动手指弯曲仅在局部三维点可用、具有 ARP bend_all 控制且没有显式预设时工作。它估计整体弯曲，不是逐指骨精确拟合，也未训练二次元专用手模型。

## v0.3：大模型识别 + 角色投影拟合

本版实际接入 RTMW 133 点全身模型（官方 `rtmw-dw-x-l`，输入 384×288），通过 RTMLib / ONNX Runtime 在本机 CPU 推理。保留 MediaPipe 快速模式。RTMW 提供二维定位，MediaPipe 只提供匹配人物的估计深度；RTMW 不是本插件中的三维重建模型。若深度估计失败，会明确提示平面初始姿势。

### 当前电脑最短流程

1. 从磁盘安装 `ScreenshotPose_v0.5.0.zip`，重启 Blender。
2. 选中 Velina 的 `rig_D`；模型选择 **高精度 · RTMW 大模型**。本机独立环境和两个 ONNX 模型已准备好。换电脑先准备基础环境，再点 **准备高精度模型**。
3. 选原始截图，点击识别。不需要导入之前的人工校正示例。此图的新模型自动将左手腕定位到了膝前。
4. 保持 **图片优先 + 估计深度**，开启 **贴合原图并匹配相机**。此图勾选双脚接地，右手 V 预设；应用强度建议 1。
5. 勾选插入关键帧后应用。界面显示拟合前后的投影误差。
6. 点 **创建并切换到匹配相机**查看匹配视角。该按钮新建插件相机，并调整渲染画幅为参考图片尺寸；可以点 **恢复原相机与画幅**还原。

### 技术实现与边界

- 133 点完整输出保存在 JSON 的 wholebody；原有 33 点接口继续可用。脸部和手指的全部点尚未驱动到角色，手势仍为显式 ARP 预设。
- 高精度模式使用人体检测，按画面面积从大到小排序选人，支持最多 4 人。空白图不会绕过检测生成虚假骨架。
- 拟合使用当前角色已求值的肩、肘、腕、髋、膝、踝构建四条运动链，固定角色骨长。使用置信度加权、稳健误差、初始姿态正则化和有界旋转求解。
- 接地启用时，脚踝位置作为固定端点，腿部只调整膝盖绕髋踝轴的弯曲方向；不以牺牲脚部接地来降低图片误差。
- 使用正交 / 弱透视相机近似，求解有限角度的视角、画面缩放与平移，不恢复真实焦距或绝对相机距离。镜像/朝向修正不为零时，需要先关闭并重建。
- Blender 实际骨架回写后再次计算投影误差。如果没有改善或接地漂移超限，自动退回拟合前姿势。低误差只说明贴近输入关节点，不保证输入识别正确、真实三维准确或身体无穿插。
- v0.3 投影拟合部分只调整双臂和双腿；v0.4 可在之后使用局部模型覆盖头部与掌心朝向，未实现完整解剖关节限位、网格碰撞或手掌贴膝约束。非均匀缩放的骨架对象暂不支持此拟合。
- 3D 视图内对关节点的局部 X/Z 修改参与拟合；图片校正保存的关节点和置信度也参与。现有动画工程需打关键帧以保持渲染姿势。
- 创建相机是单独的显式按钮，不会在每次应用姿势时替换原相机。相机与姿势恢复分别操作。

## 最短操作流程

1. 选中角色身体或控制骨架，点 **使用当前选中的角色**。Gwen 对应 `Gwen | rig`；Velina 对应 `rig_D`。
2. 选择 PNG/JPG/WebP 截图，或者点 **截图并识别**，切换到参考图片后框选。
3. 点 **识别截图 → 生成关节点**。后台处理时 Blender 可以继续操作；状态区显示进度。
4. 点 **查看图片上的识别结果** 检查左右及遮挡。选择 **查看并编辑关节点** 可在 Blender 内修正。
5. 点 **应用到当前角色**。默认只改变当前姿势；勾选 **在当前帧插入关键帧** 才写动画。
6. 不满意时点 **恢复应用前的角色姿势**，还原骨骼姿态、已识别的 FK 开关和原 Action。

关键帧会写入原 Action 的副本，原动作被保留。多次调整后，“恢复”回到这轮第一次应用前的状态；确认一轮结果后可保存工程，下一轮需要新的恢复基准时先恢复或使用新的角色副本。未打关键帧的姿态可能在切换时间帧或动画求值后被现有动画覆盖。

## 游戏 / 二次元与手动校正

先尝试自动识别。若没有识别到人物，或衣服、长发、遮挡、夸张比例让结果不准确：

1. 选择图片，点 **手动关节点（无需识别）**。
2. 插件创建参考图片和 20 个关节点。这是模板，不是自动识别结果。
3. 点 **查看并编辑关节点**，在正视图逐个选择关节，按 **G** 移到截图对应部位。
4. 用 **G → Y** 调整前后深度，或切到侧视图修正。单张图片不能唯一确定深度，需要人工判断。
5. 点 **刷新骨架连线** 查看修改，再点 **应用到当前角色**。

关节名 `.L/.R` 指人物自身左右。默认正面人物的左手显示在图片右边。低可见度关节使用方框；它们仍会应用估计值，建议修正，或在骨骼映射里取消该部位。自动识别最多返回 4 人；“人物序号”从 1 开始，顺序由检测器决定，建议先把目标人物裁切为单人图片。

“按图片校正”使用截图投影，便于对齐轮廓；“估计三维”使用模型推测的空间关节。深度、镜像、朝向修改后需点击 **按参数重建关节点**，这会替换手动移动的关节点。参考图在图片或混合模式、未镜像且朝向为零时显示。3D 视图内移动的关节点保存在 `.blend` 中，JSON 导出不包含这些移动；在原图校正窗口保存的修改会包含在 JSON 中。

## Animation Retargeting

已有的 Animation Retargeting 不负责图片识别，本插件补上这一步。可以直接使用本插件的“应用到当前角色”，也可以：

1. 校正关节点后点 **生成带关键帧的源骨架**。
2. 得到 `Screenshot Pose · Source`，具有 T 姿势静止骨架和当前帧的姿势关键帧。
3. 在 Animation Retargeting 中把它设为 Source，选择目标角色，设置骨骼映射，并按该插件原有流程对齐静止姿态、应用和烘焙。

外部重定向仍需要对齐两个角色的静止姿态。新插件没有自动修改 Animation Retargeting 的配置。

## 支持范围与限制

- 身体 17 个部位：骨盆、脊柱、胸、颈、头、左右上臂/前臂/手掌/大腿/小腿/脚。
- Gwen 和 Velina 的 Auto-Rig Pro 控制骨已经实测；包含 Rigify、Mixamo、常见 MMD/中日文骨名的匹配规则。其他绑定需核对映射，不能保证所有自定义绑定一键适配。
- 自动切换已识别 Rigify / Auto-Rig Pro 的手脚 FK 开关。不删除约束，不改角色网格、静止骨骼长度或对象变换。
- 受旋转约束或驱动器直接控制的映射骨会跳过，并在结果中提示改选 FK 控制骨。
- 身体使用旋转重定向；可选“双脚接地”根据腿长降低骨盆并求解两腿，不恢复截图中的绝对位置。接地以脚踝加高度余量为目标，不是鞋底网格碰撞；高跟鞋、衣物和身体穿插仍需调整。
- 脚方向仍是粗略估计；头掌可启用 v0.4 局部朝向。ARP 的 V / 握拳 / 张开预设优先于自动弯曲，仍是明确选择的预设。表情、精确头部转向、布料碰撞和连续视频不在此版本范围。
- 手动模板可用于二次元，但并未声称训练了专门的动漫姿势模型。
- Blender 最低声明为 4.2，实际完整测试版本为本机 **5.2.0 LTS**；其他版本尚未实测。
